# 行程与外部链接

## Google Maps 路线

- 点到点和多站路线使用 Google Maps；多站路线按行程顺序设置 `origin`、`waypoints`、`destination`。
- 时间轴的“Google 路线”表示**上一站 → 当前站**。没有可靠上一站时才使用地点地图，并命名为“Google Maps”。
- 每张时间轴卡先提供当前动线的 Google 路线 / 地图，再按内容追加可用的内部跳转。

## 时间轴内容与内部跳转

- 餐厅、午餐、晚餐、Aperitivo、小吃：`查看餐厅` → 餐厅子 Tab。
- 酒店、寄存行李、返回酒店：`查看住宿` → 住宿子 Tab。
- 景点、博物馆、门票、地标、体验：`查看景点` → 景点子 Tab。
- 购物、伴手礼、店铺：`查看购物` → 购物子 Tab。
- 点名甜点、购物或小吃店时，除内部跳转外还要直接提供该店 Google Maps。
- 逐条核对日程的正餐，不得因同一时段另有小吃、购物或景点而遗漏。行程中提及顺路购买 / 伴手礼 / 特产时，也必须写入对应 Day 的时间轴，注明品类；已核对具体店铺时附地图。
- 默认不要在时间轴展示“门票待确认”“班次待确认”等状态标签；状态留给景点 / 交通卡和检查清单。

## 各类地点卡

- **景点**：每张卡均有 `Google Maps` 和“小红书搜索”（景点名 + 城市）。需要预约才额外显示可靠的“官网购票”和“查看检查清单”；后者跳至对应门票 / 预约确认卡。无需预约则不显示这两项。
- **购物**：不得只搜索街区或泛称；先核对匹配品类的具体店铺和地址。显示“地图定位：店名 · 地址”，在按钮旁注明“这家店仅供参考，也可在附近寻找其他店”。
- **住宿**：每个实际住宿卡有地图和“查看检查清单”，后者跳至酒店订单确认卡。只有用户明确要求、住宿名和日期明确时才加 Booking 入口。
- **餐厅**：每张餐厅卡均有 `Google Maps` 和“小红书搜索”（餐厅名 + 城市）；电话已在计划或已核对时附 `tel:` 一键拨号。地址无法核实时标为待确认，不编造。
- **小吃 / 甜点 / 咖啡 / Aperitivo**：每张卡均有 `Google Maps` 和“小红书搜索”（店名 + 城市）。
- **当地体验**：每项有 `Google Maps`，链接到实际场地或集合点；无固定地点时写“集合点待确认”，不能用泛泛城市搜索代替路线。
- 门票链接只能使用用户提供或已核对的官方页，按钮名称为“官网购票”；无可靠官网不要创建按钮。

## 每日收尾

- 每个跨城 / 跨湖日需显示去程、当地活动与返程，不能把返程藏在上段说明里。
- 除离开日外，最后活动、晚餐或夜间体验后必须增加“最后一站 → 酒店”卡和 Google 路线（前提是住宿已知）。
- 离开日以“最后一站 → 机场 / 离境车站”收尾，使用实际离境地点；不再添加回酒店路线。
- 餐饮地点与时间冲突时仍保留具体餐厅名，并明确“地点待确认”，不要静默替换。
